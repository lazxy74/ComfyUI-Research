# 10. 从 0 手搓 ComfyUI 完整 Workflow

[返回首页](../README.md)

## 一、为什么要做这个实验

前面的 ComfyUI 调研已经完成了多个 Workflow：

- SDXL Base + Refiner
- SDXL + LoRA
- SDXL + ControlNet
- SDXL + IPAdapter
- AnimateDiff 视频生成
- LivePortrait 数字人
- F5-TTS 语音生成

这些实验已经让我能够：

> **导入别人制作好的 Workflow → 看懂节点 → 修改输入 → 成功运行**

但这和真正掌握 ComfyUI 仍然存在一个明显区别：

> **如果没有别人提供的 Workflow，能否从一个实际需求出发，自己设计节点、判断数据流并完成连接？**

因此下一阶段不再单纯追求“找到一个能运行的 Workflow”，而是尝试：

> **从 0 开始手动搭建一个完整的数字人 Workflow。**

---

# 二、从“会用 Workflow”到“会设计 Workflow”

目前最大的学习断层是：

```text
会看懂 Workflow
        ≠
会自己搭 Workflow
```

前面的实验更多是在学习：

```text
别人已经设计好的方案
        ↓
理解每个节点
        ↓
运行
```

而真正需要掌握的是：

```text
实际需求
   ↓
拆分任务
   ↓
确定每个阶段需要完成什么
   ↓
寻找对应节点
   ↓
判断节点输入 / 输出
   ↓
连接数据流
   ↓
调整参数
   ↓
运行与排错
```

因此本实验的重点不是“重新抄一个 Workflow”，而是学习：

> **一个 Workflow 是如何从需求一步一步设计出来的。**

# 四、第一步：先从需求拆 Workflow

假设需求是：

> **让一张人脸按照一个人的表情和动作运动，并让它说出指定文字，最后输出一个有声音的数字人视频。**

不要直接去搜索 Workflow。

首先把需求拆成 4 个任务。

---

## 任务 1：获得一个人脸

输入：

```text
Source Image
```

作用：

> 确定“这个数字人是谁”。

因此需要：

```text
Load Image
```

输出：

```text
IMAGE
```

---

## 任务 2：让人脸动起来

需要两个输入：

```text
Source Image
+
Driving Video
```

输出：

```text
Video / Frames
```

使用：

```text
LivePortrait
```

逻辑：

```text
Source Face
     +
Driving Video
     ↓
LivePortrait
     ↓
Digital Human Video
```

这里最重要的理解是：

### Source Face

回答：

> **谁在动？**

### Driving Video

回答：

> **怎么动？**

### LivePortrait

回答：

> **把 Driving Video 中的表情和运动迁移到 Source Face。**

---

# 五、任务 3：生成声音

输入：

```text
Text
```

如果使用参考音色，还需要：


输出：

```text
Audio
```

# 七、最重要的学习方法：看“数据类型”

ComfyUI 不能简单理解为：

> “看到节点就连起来。”

真正的逻辑是：

> **一个节点输出什么数据，另一个节点需要什么数据。**

例如：

```text
Load Image
    ↓
IMAGE
```

因此它可以连接到需要：

```text
IMAGE
```

作为输入的节点。

同样：

```text
TTS
 ↓
AUDIO
```

后面的节点必须能够接受：

```text
AUDIO
```

---

## 常见的数据流思维

以后看到一个节点，首先问三个问题：

### ① 它需要什么？

例如：

```text
需要 IMAGE
```

### ② 它输出什么？

例如：

```text
输出 MODEL
```

### ③ 输出的数据下一步应该去哪？

例如：

```text
MODEL
 ↓
KSampler
```

所以：

> **理解节点，不应该只记节点名称，而应该理解节点的输入和输出。**

# 十、手搓时每个节点都问三个问题

以后每加入一个节点，都回答：

### 1. 为什么需要这个节点？

例如：

> 我要把源人脸输入 Workflow，因此需要 `Load Image`。

### 2. 为什么选择这个节点？

例如：

> 因为这个节点能够输出 IMAGE，而下一个处理节点需要 IMAGE。

### 3. 它应该连接到哪里？

例如：

```text
Load Image
     │
     │ IMAGE
     ↓
LivePortrait Cropper
```

这三个问题是本次训练的核心。

---

# 十一、完整数字人 Workflow 的模块化设计

最终不要把所有节点混成一大团。

建议按照功能划分成：

```text
┌─────────────────────────┐
│       ① 人物输入        │
│ Source Image            │
│ Driving Video           │
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│       ② 数字人生成       │
│ LivePortrait            │
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│       ③ 语音生成         │
│ Text → TTS → Audio      │
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│       ④ 最终合成         │
│ Video + Audio            │
└────────────┬────────────┘
             ↓
        Final Video
```

这样以后排错也更容易。

例如：

```text
视频有问题
→ 检查 LivePortrait 模块

声音有问题
→ 检查 TTS 模块

声音正常但视频没声音
→ 检查最终合成模块
```

# 十三、这次实验真正想掌握的能力

最终不是要求记住：

```text
某某节点 → 某某节点
```

而是形成下面的思维：

```text
需求
 ↓
需要什么结果？
 ↓
需要哪些中间结果？
 ↓
每个中间结果由什么模块产生？
 ↓
每个模块需要什么输入？
 ↓
输入对应什么数据类型？
 ↓
寻找可以完成任务的节点
 ↓
连接
 ↓
运行
 ↓
根据报错排查
```

例如：

> 我要生成一个有声音的数字人。

可以自动拆成：

```text
数字人
→ LivePortrait

声音
→ TTS

视频 + 声音
→ Video/Audio Merge
```

再继续往下拆：

```text
LivePortrait
→ Source Image
→ Driving Video
→ 人脸处理
→ Motion Transfer
→ Video

TTS
→ Reference Audio
→ Reference Text
→ Generation Text
→ Audio
```

这才是真正的 Workflow 设计能力。
